2.如何提升 Agent 应用中多 Skill 调用的准确度？
本质是做好路由决策和参数映射，解决调用哪个 Skill 和如何调用 Skill 的问题，能从5个层级去解决。
优化路由决策：
语义去重与边界隔离，避免 Skill 描述重叠，描述必须包含触发条件、解决能力和边界；
动态路由提示，系统提示词中强制要求 Cot，先输出选择理由，再输出调用指令，强制 LLM 验证匹配度；
分类器前置，对高频易混淆场景，训练一个轻量级文本分类模型（如BERT-tiny）做前置硬路由，绕过大模型的模糊判断;

精准参数填充:
结构化Schema强化，增加Json实例；
做一层校验与修正，调用前先跑规则校验，拦截无效参数并触发 LLM 自我修正重试，而非直接报错；

编排范式升级:
DAG工作流，将复杂 Skill 工作拆解为DAG编排，替代纯 Prompt 驱动，实现复杂依赖，仅将叶子节点决策权交给 LLM，减少自由发挥空间；
ReAac + 状态机，在 Agent 循环中引入状态记忆，记录已调 Skill 和返回结果，避免重复调用和死循环;

工程结构兜底:
超时与熔断，单 Skill 调用超时阈值失败后自动降级，或触发人工标记；
结果一致性校验，对多个 Skill 返回结果做冲突检测，自动触发重新规划或置信度投票；

数据闭环迭代：
构建评测集，收集错误 case，标注正确 Skill 和参数，每次迭代后做回归测试；
在线反馈埋点，记录大模型的决策日志，定期用失败样本做 SFT 或构建负样本用于 Prompt 优化。
